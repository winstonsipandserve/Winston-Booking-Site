# CLAUDE.md

This is the Claude Code-facing adapter for this repository. Shared project, business, technical, and development knowledge lives in `docs/`; keep Claude-specific instructions here and Claude tooling under `.claude/`.

Only the marked Next.js block at the top of `AGENTS.md` is generated by `next dev`. The remainder of that file is maintained separately for Codex.

## Read Before Planning or Editing

Read the documents relevant to the task before planning or changing code. Do not infer domain rules from code alone.

| Topic | Canonical document |
|---|---|
| Development workflow, approval gates, Git, verification, coding conventions | [docs/development.md](docs/development.md) |
| Business rules, pricing, membership, domain concepts | [docs/business.md](docs/business.md) |
| Current application behavior | [docs/features.md](docs/features.md) |
| End-to-end processes | [docs/workflows.md](docs/workflows.md) |
| Stack, code layout, services, environment | [docs/architecture.md](docs/architecture.md) |
| Models, enums, relationships, constraints | [docs/database.md](docs/database.md) |
| Locked-in design and engineering decisions | [docs/decisions.md](docs/decisions.md) |
| Known bugs, deferred work, unverified areas | [docs/roadmap.md](docs/roadmap.md) |

`docs/decisions.md` is an implementation gate. If a task requires deviating from a recorded decision, raise it before implementation. When a change makes shared documentation inaccurate, update the relevant document in the same change.

## Claude Code Tooling

### Skills (`.claude/skills/`)

Use these when the task matches; don't reinvent what they already encode.

**Project-specific:**

- **`paymongo-integration`** — payment and webhook work.
- **`booking-conflict-prevention`** — booking creation, availability, or scheduling logic. Any task using it must verify the exclusion constraint is actually present in the database, not assume it survived a migration.
- **`prisma-schema-conventions`** — any edit to `schema.prisma`.

- **`vibe-sec`** — web-application security implementation and security reviews.

These skills contain task routing and verification checklists. The linked files under `docs/` are authoritative for current project facts.

**General design and motion** (installed via `npx skills`, not project-specific): `impeccable` (broad frontend audit and polish), `emil-design-eng` (UI craft), `animate` (build an animation), `review-animations` (critique motion), `improve-animations` (codebase-wide motion audit), `prototype` (build variants to choose between). Reach for these on visual polish passes. `impeccable`'s hook and image-generation features are off by default — read its own SKILL.md before enabling them.

Five skills (`apple-design`, `ask-sonner`, `pick-ui-library`, `animation-vocabulary`, `find-animation-opportunities`) were removed as a poor fit for this project. Don't reinstall without a concrete reason.

**Deliberately not skills:** the git workflow and browser verification are manual gates — an ambient skill would conflict with them.

### MCP Servers

- **Supabase** — OAuth-authenticated, **read-only**, scoped to this project. Docs, database inspection, and debugging only.
- **Playwright** — browser-based verification.
- **Context7** — current Next.js / Prisma / PayMongo / Auth.js documentation lookups.
- **Resend** — send/list/cancel emails, delivery logs, domain verification. Use it to confirm email delivery instead of checking the Resend dashboard by hand.
