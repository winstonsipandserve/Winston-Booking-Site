## Build Status

- **Stack**: Next.js 16 (App Router) + TypeScript, Prisma 6.19.3, Supabase (Postgres/RLS/Storage), Auth.js v5, PayMongo (Checkout Sessions API), Resend, Tailwind v4 (CSS-first `@theme`, no config file). Deployed to Vercel.
- **Schema**: 19 Prisma models (16 original, including `Bulletin` — later reshaped/unified, not newly added — + `MemberActivationToken`, `PasswordResetToken`, `MembershipPayment`). `booking_no_overlap` exclusion constraint and RLS deny-all (all tables, `anon`+`authenticated`) both live as isolated migrations, master SQL under `prisma/manual-sql/`. Resource inventory: 1 tennis court, 3 pickleball courts, 1 tennis sim, 2 pickleball sims, 2 golf sims.
- **Booking + payment flow**: Complete end-to-end, now member-aware. Anonymous: announcement gate → 5-step wizard → hold created on Confirm (`customerId: null`, provisional non-member pricing) → Payment page (reference shown immediately; Pay Now attaches customer, re-prices member-aware, confirms if price changed) → PayMongo Checkout (auto-redirect) → `/book/confirmation`. Logged-in member with an active `Membership`: `/book` detects the session server-side, hold creation prices at the member rate and attaches `customerId` directly (no PATCH round-trip), member-tier durations/pricing surface throughout the wizard, guest-count UI is hidden, and Payment skips straight to a "Booking under {name} ({email})" summary. Every step, including Payment, is on brand tokens. The session-aware member direct-booking path now also supports full-or-nothing F&B-credit redemption: if the member's `Membership.creditBalanceCentavos` fully covers the grand total, `POST /api/bookings` confirms the booking instantly (no PayMongo checkout) and debits the credit atomically — see the 2026-08-31 Completed Log entry.
- **Marketing site**: All 6 pages done — Home, Book Now, News, Café & Bar, Membership (info + `/membership/apply`), About. Home verified against a real mock UI. Navbar `fixed`, transparent-over-Hero → solid-on-scroll. `/book` now has `Navbar`/`Footer` and is on brand tokens end-to-end, same as every other page. Placeholder content pending client input: Home Hero copy, About's Our Story, Footer contact info, Café & Bar hours/photos, News social links.
- **Auth**: Email/password, live for admin (`credentials` provider) and member (`member-credentials` provider), JWT sessions, no adapter. Every `/api/admin/*` route + `(protected)/layout.tsx` require `role === 'admin'`. `/account` gates on `role === 'member'`, shows real `Customer`/`Membership`/`Booking` data. Member sign-in on `/login` is client-side `signIn()` (Navbar updates immediately, no tab-switch needed) with a password show/hide toggle; the public Navbar's Sign Out (desktop + mobile) now requires confirming a modal first — see the 2026-08-31 Completed Log entry.
- **Forgot password**: Live end-to-end — `PasswordResetToken` (1hr expiry), enumeration-safe `/api/auth/forgot-password` (always 200), `/api/auth/reset-password`, `/forgot-password` + `/reset-password` pages.
- **Membership application/approval**: Submission (`/membership/apply`) → admin review (`/admin/memberships`) → approve/reject mutation, live. Approval no longer creates a `Membership` directly — it only flips status + sends a "complete your payment" email with a `/membership/pay/[id]` link. `Membership` + credit ledger + `MemberActivationToken` are now created by the PayMongo webhook on confirmed tier-activation payment. Rejection is unchanged — sends a branded email with the admin's reason.
- **Membership tier-activation payment**: Live end-to-end — `POST /api/membership-payments` (create-or-resume PayMongo checkout for an approved application, new `MembershipPayment` model) and public `GET /api/membership-applications/[id]` (status-check endpoint, tier/status/hasMembership only, no PII) back a customer-facing `/membership/pay/[id]` (ledger + Complete Payment) and `/membership/pay/confirmation` (polling, mirrors `/book/confirmation`). Self-service renewal for already-expired members is now also live — session-gated `POST /api/account/membership-renewal`, public `GET /api/membership-payments/[id]`, `/account/renew` + `/account/renew/confirmation`, `MembershipStatusCard`'s "Renew Membership" CTA — see the 2026-08-29 Completed Log entry. Admin-side manual fallback also live — `POST /api/admin/memberships/[id]/send-renewal-link` + public `POST /api/membership-payments/[id]/checkout` back `/membership/renew/[id]`, surfaced via a "Send Renewal Link" button on `/admin/memberships/[id]` (only when that customer's membership is expired) — see the second 2026-08-29 Completed Log entry.
- **Transactional email**: `buildBrandedEmail` (shared layout) has 9 consumers — activation, rejection, forgot-password, booking confirmation, membership-payment-link, membership-expiry-reminder, membership-expired, membership-renewal, renewal-payment-link — all built and live, booking confirmation firing from the real PayMongo `payment.paid` webhook, activation firing from that same webhook's membership-payment branch (first-time only), and renewal firing from the same branch's new renewal path (with an optional/always-present receipt block: activation fee / F&B credit / total paid). Sending from verified domain `no-reply@winstonsipandserve.club`, reply-to `winstonsipandserve@gmail.com`. Membership expiry/renewal reminders are now live — see the 2026-08-28 Completed Log entry.
- **Admin panel**: Dashboard (5 stat cards, 3 recharts charts, Recent Bookings + Pending Applications lists — UI-complete, now wired to real Prisma queries via `getDashboardData()`), Bookings (list/detail/reschedule), Memberships (list/detail + approve/reject; list's status filter now splits on the derived display status — Pending/Awaiting Payment/Active/Expired/Rejected — not the raw `ApplicationStatus` enum), Resources & Pricing (tabbed Courts/Simulators/Guest Fee — resources are edit (pricing) + disable/enable only, no create/delete; Pricing/Add-on rows now have full create/edit/delete; Guest Fee stays edit-only, permanently, by design), Bulletin (full CRUD + optional image upload; 6-category enum, each with its own required-field rules — `affectedFacility`/`impact`/`action`/`eventStartAt` required for all categories, `imageUrl`/`eventEndAt`/`expiresAt`/CTA required only for categories that need them — surfaced on `/news`/`AnnouncementGate` with shared `expiresAt`/sort logic) — all live, gated by `(protected)/layout.tsx`. Not built: admin-side password reset, rate limiting, additional roles.
- **Known dev-environment quirks** (mirrors CLAUDE.md's own Known Issues): `middleware.ts` does not execute locally (Next 16/Turbopack/Windows) — every gated route has its own working `auth()` check doing the real enforcement; re-verify against `staging` before assuming this is dev-only. The Browser pane doesn't composite frames in this environment — prefer DOM/class-based checks over `getComputedStyle`/screenshots for VERIFY.
