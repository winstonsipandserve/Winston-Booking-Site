**Entry format (going forward):** Completed Log entries should be 1–3 sentences — what changed, why (only if the decision isn't obvious), and current status. Skip VERIFY step-by-step narration, exact test data/scripts, row counts, and routine confirmations (`tsc` clean, `git status` matches scope, cleanup done) — those are true of every prompt by convention, not per-entry information. Full pre-2026-08-28 history, including every original VERIFY pass, is preserved verbatim in `PROGRESS_ARCHIVE.md` — grep it for a date or keyword and read only the matched lines; don't read it in full.

## Build Status

- **Stack**: Next.js 16 (App Router) + TypeScript, Prisma 6.19.3, Supabase (Postgres/RLS/Storage), Auth.js v5, PayMongo (Checkout Sessions API), Resend, Tailwind v4 (CSS-first `@theme`, no config file). Deployed to Vercel.
- **Schema**: 20 Prisma models (16 original, including `Bulletin` — later reshaped/unified, not newly added — + `MemberActivationToken`, `PasswordResetToken`, `MembershipPayment`, `CheckInLookupAttempt`). `booking_no_overlap` exclusion constraint and RLS deny-all (all tables, `anon`+`authenticated`) both live as isolated migrations, master SQL under `prisma/manual-sql/`. Resource inventory: 1 tennis court, 3 pickleball courts, 1 tennis sim, 2 pickleball sims, 2 golf sims.
- **Booking + payment flow**: Complete end-to-end, now member-aware. Anonymous: announcement gate → 5-step wizard → hold created on Confirm (`customerId: null`, provisional non-member pricing) → Payment page (reference shown immediately; Pay Now attaches customer, always re-prices at non-member rate regardless of any matched `Customer`'s membership status, confirms if price changed for other reasons e.g. a live pricing edit) → PayMongo Checkout (auto-redirect) → `/book/confirmation`. Member rate and F&B credit are only available via the session-aware member path below — see the 2026-09-01 Completed Log entry. Every step, including Payment, is on brand tokens. The session-aware member direct-booking path now also supports full-or-nothing F&B-credit redemption: if the member's `Membership.creditBalanceCentavos` fully covers the grand total, `POST /api/bookings` confirms the booking instantly (no PayMongo checkout) and debits the credit atomically — see the 2026-08-31 Completed Log entry.
